# 護理師在病房的一天：24hr（NURSE24HR）

免安裝網頁職場模擬遊戲。**整個遊戲就是一個檔案：`index.html`**。
雙擊用瀏覽器打開就能玩；丟到任何靜態網站空間就能讓別人用手機玩。

## 資料夾說明

| 路徑 | 用途 |
| --- | --- |
| `index.html` | **遊戲本體（唯一需要維護的程式）**，圖片與音效已內嵌，不需網路 |
| `docs/EVENT_GUIDE.md` | 事件、數值與 A/B/C/D 選項的設計手冊 |
| `public/assets/` | 原始美術圖檔備份（遊戲不會讀取這裡，圖已內嵌在 index.html） |
| `archive/` | 舊的 React/Vite 版本與舊架構文件，**已停止維護**，僅供參考 |

## 個案排程格式（事件與個案解耦）

每位個案的 `schedule` 陣列，每一項由個案自己決定「哪個事件、幾點、多大機率」：

```json
"schedule": [
  { "eventId": "ROUTINE_ORAL_MED",   "time": "09:00", "probability": 1.0 },
  { "eventId": "ROUTINE_CHECK_SUGAR", "window": ["11:00", "12:00"], "probability": 0.8 },
  { "eventId": "EMERGENT_BONE_PAIN", "window": ["23:30", "00:30"], "probability": 0.65 }
]
```

- `time`：`"HH:MM"`（或分鐘數，570 = 09:30），到點觸發。
- `window`：`["HH:MM","HH:MM"]`，每局在區間內隨機挑一個時間點，可跨午夜。
- `probability`：到點時擲一次，擲中才響鈴。
- 一份排程涵蓋 24 小時；只有落在本班時段內的項目會觸發（白班 08:00–16:00、小夜 16:00–24:00、大夜 00:00–08:00）。排在開班時刻的事件開局就響。
- 事件類別（常規／特殊／突發）由 `eventId` 對應的範本決定，不必另寫。
- **沒寫 `time`／`window` 的項目，以及舊格式（`routines`／`scheduled`／`random`）仍沿用舊的「依階段隨機推進」，不受影響。** 可以逐位個案慢慢改成新格式。
- `SHIFT_TUNING.routineRate` 只調整舊格式的常規事件頻次；全部個案都改成新格式後可移除。
- 驗證用腳本：`python3 tests/schedule_check.py`（用合成個案檢查時間、機率、班別過濾）。

## 《病房事件》分類（category: "ward"）
- 不屬於任何病房：發生時在護理站響起（護理站旁出現閃爍紅色「🏥 病房事件」徽章），玩家必須走回護理站才能處理；抵達護理站自動開啟事件視窗，已在站內時直接開啟，離站時點護理站可走回。
- 範本寫在 `WARD_EVENT_TEMPLATES`、排程寫在 `WARD_SCHEDULE`（`{eventId,time,probability,excludeShifts?}`，不綁個案），目前排程為空，只有一個未排入的測試範本 `WARD_TEST_SAMPLE`。
- 範本可選 `deadlineMinutes` + `onExpire:{endShift}` 或 `{event:"另一個病房事件ID"}`；選項欄位同一般事件（需完整填 time/stress/stamina/hydration/records/safety/favor）。
- 實作：以 `WARD_PATIENT`（`isWard:true`、assignedRoom `'ST'`）當作事件的虛擬病人，不影響房間卡片；不鎖速度（非 emergent）。
- 測試：`python3 tests/ward_check.py`。
- 已建立 5 個病房事件（電視打不開／馬桶壞了／馬桶塞住了／詢問病情／電話禮儀度測試）。前 4 個時限 60 分鐘，逾時 → 結局「家屬毆打護理人員」；電話禮儀度測試無時限。
- 排程（`WARD_SCHEDULE`）：每個事件每班最多隨機觸發一次，白班 10%（08:00–15:00）、小夜 6%（16:00–23:00）、大夜 3%（00:00–07:00）；電話禮儀度測試只在白班。
- 病人死亡後（`killPatient`）自動產生特殊事件 `SPECIAL_END_OF_LIFE_CARE`「遺體護理」（無時限，需到該床；死亡卡片顯示「☠ 待遺體護理」，處理完變回「☠ 死亡」）。選項 A 細心打扮／B 隨便擦／C 請家屬擦／D 先去其他床（保留）。
- 選項新增欄位 `endShiftP`（0~1）：搭配 `endShift` 使用，選擇該選項時以此機率觸發結局（省略 = 必定觸發）。遺體護理 B 10%、C 20% 觸發「家屬毆打護理人員」。

## 入院流程（已啟用 ADMISSION.enabled=true）
- 抽選規則見上；抽中後白班 60% 門診／40% 急診，小夜 80% 門診／20% 急診。
- 急診：病房事件「急診入院通知」(護理站，3 分、壓力+3) → 鋪床(2 分) → 病人抵達量VS（特殊/突發機率×2）→ 入院評估&詢問病史(5 分、體力-2) → 建管路(管路數×3 分、體力-管路數；PICC/氣切不建) → 完成入院手續(3 分、體力-1、紀錄+1)。
- 門診：右上提示「［床號］簽床組已簽床，門診預入院」後同上（無來電、VS 機率不加倍）。
- 鋪床完成才換上新個案（舊個案列入 gameState.retiredIds 不再被抽）；完成入院手續後，新個案的 schedule 中「尚未過去」的時間點才接上本班（已過的略過，window 只在剩餘區間抽）。
- 測試：tests/admit_flow_check.py [day|evening]
- 急診來電限時 30 分鐘：逾時未接 → 本次入院取消，床位回到空床可重新抽選（tests/admit_expire_check.py）。
